# /kickoff

Цель — за 20–30 минут получить репозиторий, в котором `make check` зелёный и в котором четверо могут работать, не мешая друг другу. Типы ошибок не пишем, пока скелет не работает.

## Шаги
1. Уточни у пользователя: имя проекта (kebab-case, по умолчанию `auditgym`), название команды, где лежит репозиторий сдачи (свой GitHub или выданный организаторами) и публичный ли он.
2. Из корня комплекта: `TEAM_NAME="<команда>" bash scripts/new-project.sh <name> none`. Скрипт кладёт `CLAUDE.md` режима хакатона, скиллы, агентов и контекст, делает `git init` и первый коммит. Проект появится в `projects/<name>/`.
3. Скопируй скелет среды: `rsync -a templates/rl-env/ projects/<name>/` и переименуй пакет, если имя другое. Коммит: `chore: add rl-env skeleton`.
4. Скопируй `cases/fin-audit-env/` (`CASE.md`, `BREAKDOWN.md`, `SPEC.md`, а также `CHECKS.md`, `PLAN.md`, `TASKS.md`, если есть) в `projects/<name>/docs/`. Коммит: `docs: add case, spec and plan`.
5. Проверь скелет: `make check` локально на Python 3.11, затем `docker build -t <name> . && docker run --rm --network none <name>`. Оба зелёные.
6. Добавь лицензию (MIT, если организаторы не требуют другую) и `README.md` через `/jury-readme` в режиме skeleton.
7. Создай удалённый репозиторий и ветки по зонам: `gen`, `env`, `judge`, `qa`. В `main` попадает только то, что прошло `/verify`. Дай доступ команде.
8. Первая задача после скелета — заморозить контракты: схемы файлов эпизода, действий, наблюдений, `findings` и `truth` в `schemas/`. От них зависят все четыре зоны.

## Правила
- Никаких сторонних пакетов в ядре. Нужен пакет для разработки — только в `requirements-dev.txt` и только если без него нельзя.
- Каталог эпизодов с закрытыми файлами не кладём рядом с открытыми.
