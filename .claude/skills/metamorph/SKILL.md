# /metamorph

В кейсе: «повтор seed/действий точен, а перестановка и смена ID сохраняет ответ oracle и награду с учётом новых ID».

## Проверки
1. **Точный повтор:** два независимых процесса с одинаковыми seed, config и действиями дают побайтово одинаковые файлы эпизода, наблюдения, награды и траектории. Запускай с разными `PYTHONHASHSEED`, локалью, часовым поясом системы и текущим каталогом.
2. **Изоляция reset:** эпизод A, затем B, затем снова A — второй A равен первому. Ничего не переживает `reset` (глобальные счётчики, кэши, открытые файлы).
3. **Смена поверхности нашим параметром:** другой `surface_seed` при том же seed даёт тот же эпизод с другими ID, именами и порядком. Ответ oracle переводится по таблице соответствия ID; награда та же.
4. **Преобразование чужим скриптом:** `tools/transform.py` переставляет строки и переименовывает ID прямо в файлах эпизода (открытых и закрытых согласованно), как мог бы сделать скрипт организаторов. Среда, загруженная из преобразованных файлов, даёт ту же награду oracle. Это страховка на случай, если преобразуют не через наш генератор.
5. **Курсоры:** страницы стабильны; обход всех страниц даёт каждую запись ровно один раз в любом порядке запросов.
6. **Запрещённые источники недетерминизма:** `grep -nE "import random|time\.time|datetime\.now|uuid|os\.urandom|hash\(|set\(" src/` — каждое совпадение объяснено или убрано. Обход множеств и словарей только в отсортированном порядке; деньги и курсы без `float`.

## Шаги
1. `python -m tools.metamorph --pairs 200` (в `make score` идёт укороченный вариант).
2. Тот же прогон в контейнере `python:3.11-slim` и на машине разработчика: хэши эпизодов совпадают.
3. Расхождение сокращай до минимального seed и закрепляй тестом.
