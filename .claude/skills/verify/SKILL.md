# /verify

Цель — за 1–3 минуты ответить «готово или нет» фактами. Это не ревью (для него `/hard-review`), а проверка, что ничего не сломано.

## Фазы
Сначала `make check`: он закрывает фазы 1–4. Фаза красная — дальше не идём: чиним (или зовём агента `build-error-resolver`) и запускаем `/verify` заново.

1. **Тесты:** `python -m unittest discover -s tests -q`. Пропущенные тесты без причины и тесты без утверждений отметь в отчёте.
2. **Счёт:** `make score` — пять критериев, число пройденных проверок не ниже, чем в последней строке `docs/SCORE-LOG.md`. Падение — красная фаза.
3. **Короткий фазз:** `make fuzz SEEDS=200` — ноль брака.
4. **Детерминизм и утечки:** `python -m tools.metamorph --pairs 20` и `python -m tools.leakscan` — чисто.
5. **Чистая среда:** ядро импортируется без сторонних пакетов (`python -I -c "import auditgym"`), не обращается к сети, часам и случайности мимо `rng`. Перед контрольными точками: `docker build` и `docker run --rm --network none … make check`.
6. **Секреты и данные:** в diff нет ключей (`sk-`, `AKIA`, `ghp_`, `github_pat_`), `.env*`, реальных финансовых и персональных данных. Нашёл ключ — стоп, сообщи пользователю, значение не печатай.
7. **Diff:** `git diff --stat`. Нет случайных файлов (логи, большие бинарники, каталоги эпизодов вне `episodes/`), отладочного вывода и правок вне зоны текущей задачи из `docs/TASKS.md`.

## Отчёт
```
VERIFY: ГОТОВО | НЕ ГОТОВО
Тесты ✅ 212/212  Счёт 94.3 (было 93.1)  Фазз ✅ 200/200  Детерминизм ✅  Утечки ✅  Контейнер ✅  Секреты ✅  Diff: 6 файлов
Чинить: 1) ... 2) ...
```
Если всё зелёное и пользователь не против — коммит с понятным сообщением.

## Правила
- Не отключай проверки ради зелёного статуса: никаких новых `skip`, ослабленных допусков и удалённых seed из фазза.
- Фазу, которой в проекте ещё нет, помечай «нет», а не «✅».
