## Презентация (8 слайдов, PDF)

1. **AuditGym.** Экзамен для ИИ-аудитора. Команда, трек FinTech, ссылка на репозиторий.
2. **Проблема.** Плохая среда учит модель трюкам: угадывать ID, помечать всё подряд, полагаться на порядок строк. Нужна среда, где награду дают только за правильную находку с доказательствами.
3. **Как устроено.** История компании → книги → ошибки с записанной причиной → поверхность (ID, порядок). Агент видит только пять инструментов чтения: `list_records`, `get_record`, `get_document`, `calculator`, `submit`. Оценщик и эталон — в отдельном процессе.
4. **Четыре ошибки и два взаимодействия** (числа из `python3 -m tools.demo`):
   - дубль счёта: два счёта, один клиент, 9 475 000,00 KZT, те же позиции, оба проведены;
   - нераспределённый платёж: 234 785,43 KZT осели на «нераспределённых», счёт открыт;
   - ошибка курса: 25 220,00 USD × 503,6452, а в книге на 126 675,01 KZT иначе;
   - чужой период: документ от 27.09, проводка 01.10 внутри октября;
   - взаимодействия: частичный валютный платёж у границы периода — разрыв распределения и ошибка курса на одном платеже (I1); копия счёта, датированная вне периода, но проведённая — дубль и чужой период сразу (I2).
5. **Эталон однозначен и выводим.** Независимый решатель по открытым записям совпадает с эталоном на всех эпизодах (фазз, `python3 -m tools.fuzz`). Отвлекающие случаи — переплата, аванс, частичная оплата, возврат, повторяющаяся сумма, граница периода — ошибкой не считаются.
6. **Почему нельзя обмануть.** Оценщик вне процесса агента, эталон не выходит в наблюдения (`tools.leakscan`: 0 проблем). Атаки на награду 70/70, мутанты оценщика 35/35. Перестановка строк и смена ID не меняют награду (`tools.metamorph`: 20/20).
7. **Результаты.** Таблица политик на 200 эпизодах из `docs/RESULTS.md`: oracle 1.000, решатель 0.960, сверка −0.685, «пометить всё» −0.987, молчание −0.500. Полнота сверки по типам: 0.98 / 0.00 / 0.00 / 0.89.
8. **Ограничения и что дальше.** Синтетические книги, только продажи и дебиторка; награда не доказывает понимание учёта; обучение моделей на среде мы не запускали. Дальше: больше типов операций, валюты с 0 и 3 знаками, обучение агента.

## Защита (3 минуты)

1. Одна фраза (главная мысль сверху).
2. Слайды 3–4: что видит агент и что он должен найти; живой `python3 -m tools.demo`.
3. Слайд 6: как мы проверяли, что оценку нельзя обмануть: атаки, мутанты, утечки, метаморфные пары, CI в Docker без сети.
4. Слайд 7: среда не тривиальна — сверка не видит курсов и разрывов, эвристику обманывают отвлекающие случаи.
5. Ограничения одной фразой.

Частые вопросы:
- **Почему «пометить всё» на книгах с ошибками чуть выше молчания?** Молчание там даёт ровно −1 по формуле кейса, поэтому любая случайная угадка выше. На чистых книгах атака даёт −1 против +1 у молчания и в среднем ниже его.
- **Почему oracle получает 1.0, а не 0.998?** Мы считаем шагами осмотра только действия до `submit`; если жюри считает и `submit`, будет 0.998. Вопрос отправлен организаторам (`docs/QUESTIONS.md`).
- **Можно ли восстановить эталон по seed?** Без секрета оценщика — да, перебором малого seed (это открытые train/dev). Для закрытого прогона оценщик берёт секрет, и без него эпизод не собрать.
