# Аудит на Fable (19.11) — находки и решения

Пять независимых аудиторов читают код сами и не видят отчётов авторов. Здесь — принятые находки и что с ними делаем. Статус: `[ ]` не исправлено, `[x]` исправлено и закреплено тестом.

## 1. Данные и эталон
Независимый проверщик аудитора: 2 400 эпизодов на сетке (5 базовых валют, 0–3 иностранные, 11 смещений, 10 периодов, размеры 10–200 счетов, все типы и сценарии) — 0 нарушений равенств до ошибки, 0 пропущенных и 0 лишних срабатываний его собственных предикатов против эталона. Находки ниже — места, где проверяющий с другим разумным прочтением забракует эпизод.

| № | Находка | Решение | Статус |
|---|---|---|---|
| D1 | Доказательства `fx_error` не содержат запись курса; доказательства `allocation_gap` не содержат строк дебиторки | `fx_error`: документ, строка пересчёта, ключ курса. `allocation_gap`: платёж, счёт, строка нераспределённых, дебет дебиторки счёта, кредит дебиторки платежа | [ ] |
| D2 | Частичный платёж и возврат в валюте закрывают дебиторку по курсу дня платежа; правило не опубликовано | Закрывать пропорционально по курсу отражения счёта, курсовая разница на каждом валютном платеже; правило — в `policy.json` | [ ] |
| D3 | Законный повторяющийся счёт выставлен за услугу соседнего месяца: по начислению это ошибка периода | Близнец с периодом услуги внутри отчётного периода (например, 1–15 и 16–31); подпись дубля — в `policy.json` | [ ] |
| D4 | `period_cutoff` вносится правкой документа, книга не меняется; в 35 % случаев платёж оказывается раньше своего счёта | В чистой истории есть законно не проведённые счета соседнего периода; ошибка — провести такой счёт в отчётном периоде. Документы не меняются, разница книг — две строки на объявленную сумму | [ ] |
| D5 | Естественные конфигурации отклоняются (`base_currency: USD`, `currencies: []`, 12 ошибок при размере по умолчанию); 2 000 проводок недостижимы | Значения по умолчанию подстраиваются под соседние ключи (валюта, число ошибок под размер); таблица «сколько счетов на N ошибок» в README; верхняя граница размеров достигает диапазонов кейса | [ ] |
| D6 | 5–6 % переносов стоят ровно на `period_end`; политика не говорит, что период — полуинтервал | `"period_interval": "[start, end)"` в `policy.json` | [ ] |
| D7 | В provenance `params.scenario` содержит чужой ID счёта вместо `I1`/`I2` | Переводить в открытые ID только поля-идентификаторы | [ ] |
| D8 | Трюк «проводка позже 4 суток после даты счёта» находит `period_cutoff` с точностью 1,00 и полнотой 0,96; платёж `I1` в чужом смещении в 67 % случаев против 15 % у обычных; копия `I2` никогда не оплачена | Законная задержка проводки до нескольких недель; доля чужих смещений у `I1` как у обычных платежей; копия `I2` оплачивается с обычной вероятностью | [ ] |

## 3. Утечки и изоляция
Утечек эталона через наблюдения, `info`, тексты ошибок, объект клиента и файл результатов не найдено (61 ответ на 24 неверных запроса и полный обход; 57 поверхностных признаков на запись на 400 + 400 эпизодах — всё в пределах 0,43–0,57 AUC, кроме следующего из определений). Дешёвая политика на поверхностных правилах: −0,27 против 0,95 у честной. Время и размер ответа не отличают затронутые записи (AUC 0,47–0,60).

| № | Находка | Решение | Статус |
|---|---|---|---|
| L1 | Seed восстанавливается перебором, если агент импортирует пакет: 2^20 кандидатов за ~24 с по первому курсу | Секрет оценщика, заданный при старте `serve` (переменная окружения или файл), подмешивается в корень потока; по умолчанию пуст. В записке: закрытые seed лучше брать не короче 128 бит. Порядок вызовов потока не должен давать дешёвый фильтр по первому наблюдению | [ ] |
| L2 | Политика в одном процессе с `run_episode` видит `seed` в кадре вызывающего | Ограничение в записке: в закрытом прогоне политика получает только наблюдения (отдельный процесс) | [ ] |
| L3 | Файл результатов `eval` создаётся с правами 0644 и пополняется после каждого эпизода | Права 0600 | [ ] |
| L4 | Строка длиннее 1 МиБ во время эпизода не тратит шаг и не завершает эпизод | Во время эпизода такая строка — шаг с ошибкой; для `submit` — неверная структура | [ ] |
| L5 | `provenance.params.scenario` содержит ID счёта (то же, что D7) | см. D7 | [ ] |
| L6 | Закономерности генератора: задержка проводки больше 4 дней (см. D8); счёт вне периода с платежом — всегда ошибка (нет законного двойника); круглая сумма отличает разрыв от переплаты (AUC 0,85); платёж `I1` в чужом смещении в 62 % случаев | Законный предоплаченный счёт следующего периода; переплаты и разрывы с одинаковым распределением сумм; остальное — в D8 | [ ] |
| L7 | В репозитории отслеживается каталог `.claude/` (скиллы, заметки о хакатоне); в истории коммитов личный e-mail автора | Решить перед публикацией репозитория (вопрос к Адлету) | [ ] |

## 4. Награда и воспроизводимость
Независимый эталон аудитора совпал с нашим `judge` на 24 000 пар (0 расхождений); пять свойств §05 выполняются через сервер на шагах 1..100; точный повтор побайтовый на 21 варианте окружения; 35 своих преобразований файлов × 8 эпизодов — всё, что жюри может правдоподобно применить, проходит.

| № | Находка | Решение | Статус |
|---|---|---|---|
| R1 | `submit` с NaN, Infinity или огромным целым через клиент не завершает эпизод (ошибка сериализации превращается в `unknown_action`) | Клиент шлёт такой `submit` как неверную структуру (−1, эпизод завершён); сервер не ограничивает длину целых | [ ] |
| R2 | Ответ в пределах лимитов кейса (30 выводов × 10 доказательств × 1 000 символов кириллицей = 68 КБ) получает −1 из-за нашего лимита 64 КБ | Лимит сообщения 256 КБ | [ ] |
| R3 | `inspection_steps` не включает шаг `submit` | Оставляем; одной фразой с примером в записке о дизайне | [ ] |
| R4 | Награда на 1 ulp отличается от формулы, набранной во `float` (16 % сочетаний) | Считать буквально `max(-1.0, min(1.0, 2*f1 - 1 - 0.002*steps))` | [ ] |
| R5 | Oracle, собранный чуть иначе, получает −1: нет `explanation`, сумма `125000.0`, тип в другом регистре, все наборы доказательств подряд с повторами | `explanation` необязателен; целочисленный `float` принимается; лимит 10 считается по уникальным ID; тип и валюта нормализуются (регистр, пробелы по краям) | [ ] |
| R6 | «Первые 15 и последние 15 счетов как cutoff» даёт до +0,82 на максимальной плотности: таблицы отсортированы по дате, а cutoff-документы стоят по краям | Порядок записей в таблицах — по открытому ID, а не по дате; формулировку C1 исправить на «отрицательная награда и ниже oracle» | [ ] |
| R7 | `submit` с `episode_id` и `findings` прямо в действии даёт −1; имя действия в другом регистре не распознаётся | Принимать оба вида `submit`; имя действия и таблицы без учёта регистра | [ ] |
| R8 | Политики `reconcile` и `flag_all*` зависят от порядка строк: при перестановке награда меняется | Сортировать прочитанное по содержимому перед решением и обрезкой; `reconcile` читает книгу целиком | [ ] |
| R9 | `Env.from_files` требует `provenance.json` и `pre_*`, хотя оценщик их не читает | Эти четыре файла необязательны при загрузке | [ ] |
| R10 | `get_record("invoices", id)` может вернуть чужую запись, если `doc_id` одного счёта совпал с `invoice_id` другого (после чужой перенумерации) | Искать сначала по `doc_id`, затем по `invoice_id`/`payment_id`; BOM в файлах допускается | [ ] |
| R11 | README и записка о дизайне — заглушки; нет описания `from_files`, `surface_seed` и списка полей с ID для тех, кто будет переименовывать | Раздел в записке и README | [ ] |
