## Открытые вопросы зоны (нужно решение команды)

### 1. `make report` из README ломает `check` — серьёзно

`tools/report.py` пишет в `docs/RESULTS.md` колонку «Время, мс». `tools/checks_pack.py:175` (`readme_results_are_a_copy`) сверяет строки README с RESULTS побайтно, вместе со временем. Время на любой другой машине своё.

**Как воспроизвести.** Пересобрать RESULTS (`make report`) и запустить `python -m tools.score`. Результат: «Инженерия и объяснение 4/5, ИТОГО 98.0/100, `README results row is not in docs/RESULTS.md`». Метрики совпадают все, расходится только время. Жюри, повторившее шаг из README, увидит `CHECK: FAILED`.

**Варианты:**
- (а) убрать время из таблицы в README;
- (б) не сверять колонку времени в `checks_pack.py`;
- (в) вынести время из основной таблицы RESULTS в отдельную.

Правку в `report.py` сделаю, когда выберем вариант.

### 2. Мягкий разбор ответа расходится с документами

`findings.py` (решение `docs/AUDIT.md` R5) принимает:
- вывод без поля `explanation`;
- целочисленный `float` (`125000.0`);
- тип и валюту в другом регистре;
- повторы в `evidence_ids` (лимит 10 считается по уникальным ID).

Отдельно `actions.py` принимает голый список выводов без `episode_id` и выводы строкой JSON.

При этом `docs/CONTRACTS.md:211` и `docs/SPEC.md:139` утверждают, что `100.0` и отсутствующее обязательное поле дают −1. В тех же строках указан лимит сообщения «64 КБ», а в коде 256 КиБ (`auditgym/limits.py:12`, AUDIT R2).

Кейс говорит только «неверная структура → −1» и не определяет её границу. Если жюри проверяет буквально, мягкость может стоить пункта. Если строго, правильно оформленный по-другому ответ получит −1. Ни то, ни другое не доказано.

**Предложение.** Мягкость оставить: так решено в R5, и это защищает честного агента. `CONTRACTS.md:211` и `SPEC.md:139` выровнять под код. Если решим «строго», править нужно код и тесты `tests/judge/test_findings.py`.

### 3. `inspection_steps` не включает `submit` — вопрос организаторам

`evaluator.py` считает шагами осмотра только действия до сдачи. Oracle, сдающий ответ первым шагом, получает 1.0; если жюри считает `submit`, будет 0.998. Это описано в README, в разделе «Ограничения».

Это вопрос №9 в `docs/BREAKDOWN.md` §4. В `docs/QUESTIONS.md` он не записан и организаторам не отправлен (задача P2).

### 4. «Пометить всё» на книгах с ошибками чуть выше молчания

Свойство формулы кейса: молчание на книгах с ошибками даёт ровно −1, поэтому любое случайное попадание выше. Наши цифры по `flag_all` минус `silence`:

| Набор | Разница |
|---|---|
| train | +0.064 |
| dev | +0.052 |
| сгенерированный | +0.031 |

На чистых книгах атака получает −1 против +1 у молчания и в среднем ниже его. Формулу мы не меняем, это описано в README и RESULTS. Записано, чтобы на защите не было сюрпризом.
