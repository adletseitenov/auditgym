## Открыто

1. **Время в `docs/RESULTS.md` снято на нагруженной машине и на Python 3.12.8.** Обновить: запустить `make report` в закреплённом контейнере. Метрики при этом не изменятся.
2. **`inspection_steps` не включает `submit`.** Oracle, сдающий ответ первым шагом, получает 1.0 (иначе было бы 0.998). Сходится с официальными проверками: B3-15 (`inspection_steps = 0` → награда 1) и C14–C16 (`docs/ADAPTER.md`, «Бюджет и время»). Записано в README, раздел «Ограничения».
3. **Разбор ответа строгий** по официальным определениям (DECISIONS R). Необязательно только `explanation`: страница организаторов не называет его обязательным полем. Закрыто.
4. **«Пометить всё» на книгах с ошибками чуть выше молчания.** Разница: train +0.053, dev +0.052, сгенерированный набор +0.033. Это свойство формулы кейса: молчание там даёт ровно −1. На чистых книгах атака получает −1 против +1 у молчания и в среднем ниже его. Записано, чтобы на защите не было сюрпризом.

5. **`reset` посреди эпизода в `eval` разрешён и для загруженного эпизода.** Брошенный прогон пишется строкой `abandoned`, новый начинается с полным бюджетом (`docs/DECISIONS.md`, H, дополнение 3). Если жюри считает перезапуск попыткой, он виден в журнале по `episode_run` и `abandoned`; запретить его мы не стали, чтобы можно было проверить изоляцию `reset`.
6. **`Env(mode="eval")` без явного секрета при секрете в окружении — `EnvError("bad_secret_file")`.** Для закрытого прогона передайте `secret_file=` или `server_command=` (README «Закрытая проверка»).

7. ~~**Базовые политики `reconcile` и `flag_all*` зависят от написания ID.**~~ Исправлено Адлетом 21.11 (`8124d11`, «baselines order by content, not by ID»): политики упорядочивают записи по содержимому, ID последним. Закрыто.
